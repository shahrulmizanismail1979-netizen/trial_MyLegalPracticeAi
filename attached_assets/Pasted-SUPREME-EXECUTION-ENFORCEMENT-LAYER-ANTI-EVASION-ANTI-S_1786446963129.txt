12. EXTERNAL BLOCKER STANDARD

Something may be classified as BLOCKED only when implementation genuinely depends upon something unavailable to you, such as:

- missing external API credentials;
- third-party approval;
- inaccessible external service;
- unavailable paid subscription;
- infrastructure outside this environment;
- information only the project owner can legally or factually supply.

Even then:

DO EVERYTHING POSSIBLE UP TO THE BLOCKER.

For example:

if an API key is missing:

- integration architecture;
- secure credential interface;
- API client;
- validation;
- loading states;
- error handling;
- storage model;
- usage tracking;
- test mocks where appropriate;

then report only the final live API call as blocked.

Do NOT use one missing credential as an excuse to abandon the entire feature.
